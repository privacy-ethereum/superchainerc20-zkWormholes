# zkWormholes Circuits

Private cross-chain ERC20 token transfers using zero-knowledge proofs on the OP Stack Superchain.

## Overview

This package implements ZK circuits for zkWormholes (inspired by EIP-7503), enabling users to transfer tokens from Chain A to Chain B without publicly linking the sender and recipient addresses.

### How It Works

1. **Burn Phase (Source Chain):** User transfers tokens to a derived burn address
2. **Proof Generation (Off-chain):** Generate a ZK proof that the burn happened
3. **Mint Phase (Destination Chain):** Submit proof to mint tokens to any address

The burn address is derived from a secret known only to the sender. The nullifier (hash of the secret) prevents double-spending.

## Circuits

### 1. Slice20Bytes.circom

Extracts the first 20 bytes (160 bits) from a 256-bit input value, creating an Ethereum-compatible address.

**Inputs:**

- `in` - 256-bit input value as field element

**Outputs:**

- `out` - First 20 bytes (160 bits) as field element

### 2. UnspendableAddress.circom

Generates a burn address that is provably unspendable. Uses Poseidon hash (more efficient in circuits than Keccak) to derive the address from a secret.

**Private Inputs:**

- `secret` - Random secret generated by the sender

**Outputs:**

- `nullifier` - `Poseidon(secret)`, used for double-spend prevention
- `burnAddr` - `Slice20Bytes(Poseidon(secret))`, the 20-byte burn address

The nullifier is tracked on-chain to prevent the same secret from being used twice.

### 3. RLPEncodeEventLog.circom

Encodes ERC20 Transfer event log data in RLP format for trie verification.

**Inputs:**

- `contractAddr` - Token contract address (160 bits)
- `from` - Sender address (160 bits)
- `to` - Burn address (160 bits)
- `amount` - Transfer amount (256 bits)
- `eventSignature[256]` - Transfer event signature bits

**Outputs:**

- `encoded[2048]` - RLP-encoded event log as bits
- `encodedLen` - Actual length in bits

### 4. ProofOfInclusion.circom

Main circuit proving that a Transfer event is included in a block's receipt trie.

**Private Inputs:**

- `secret` - Secret for burn address generation
- `from` - Sender address
- `amount` - Transfer amount
- `tokenContract` - ERC20 contract address
- `proofNodes` - MPT proof nodes
- `trieKey` - RLP-encoded transaction index

**Public Inputs:**

- `receiptsRoot[256]` - Receipt trie root from block header

**Outputs:**

- `nullifier` - For double-spend prevention
- `burnAddr` - The derived burn address
- `isValid` - Whether the proof is valid
- `transferAmount` - Amount that can be minted

### 5. ZkWormholeTransfer.circom

Complete circuit for private cross-chain transfers with all verifications.

**Parameters:**

- `maxReceiptBytes` - Maximum receipt size (default: 4096)
- `maxProofNodes` - Maximum MPT proof depth (default: 10)
- `maxNodeBytes` - Maximum node size (default: 1024)

**Public Inputs:**

- `receiptsRoot[256]` - Receipt trie root
- `tokenContract` - Token contract address
- `destinationChainId` - Target chain ID

**Private Inputs:**

- `secret` - Burn address secret
- `senderAddress` - Original sender (hidden)
- `amount` - Transfer amount
- `receiptRLP` - RLP-encoded receipt
- `proofNodes` - MPT proof data

**Outputs:**

- `nullifier` - Double-spend prevention
- `burnAddress` - Derived burn address
- `withdrawAmount` - Amount for minting
- `isValid` - Proof validity

## Dependencies

- **circomlib** - Standard Circom library (bitify, comparators)
- **keccak256-june-in-exile** - Efficient Keccak256 implementation for Circom

## Building

```bash
# Install dependencies
pnpm install

# Compile a circuit (from packages/circuits/)
circom circom/ZkWormholeTransfer.circom \
  --r1cs --wasm --sym \
  -l node_modules \
  -o build/

# Generate trusted setup (requires Powers of Tau file)
snarkjs groth16 setup build/ZkWormholeTransfer.r1cs pot_final.ptau circuit.zkey

# Export verification key
snarkjs zkey export verificationkey circuit.zkey verification_key.json

# Generate Solidity verifier
snarkjs zkey export solidityverifier circuit.zkey Verifier.sol
```
